## 1. Core Concept: Why Plan-then-Execute?

When an AI agent builds software, token usage is heavily imbalanced:
- **Architectural Planning (5% to 10% of tokens)** requires a frontier reasoning model (e.g., `Gemini 4 Argon` or `Claude Opus 5.5`) capable of decomposing a complex goal into ordered, atomic steps with explicit success criteria.
- **Step Execution (90% to 95% of tokens)** consists of repetitive **ReAct** tool loops: reading files, writing targeted code, running `pytest`, and inspecting console output.

Running a frontier model for 100% of execution steps is **2× to 4× more expensive** and significantly slower. **Ai-Sup** separates these responsibilities:
1. **The Plan (`Plan`)** is generated by the **Planner (Parent)** model.
2. **The Execution (`Step` by `Step`)** is delegated to a fast, cost-efficient **Executor (Child)** model.
3. **Smart Escalation (`StepRouter`)**: if the Executor fails repeatedly on a difficult step (by default `>= 2` retries), the router automatically escalates back to the Planner to replan the workflow—as long as the remaining budget allows it.

## 2. Installation & Setup

### Prerequisites
- **Python 3.11+** (tested with Python 3.12)
- A API key for live runs. *(No API key is required to run the comparative simulation benchmark or unit tests).*

### Standard Installation (Recommended)

From the repository root (`C:\Ai-Supervisor`):

```powershell
# 1. (Optional) Create and activate a virtual environment
python -m venv .venv
.\.venv\Scripts\Activate.ps1   # Windows PowerShell
# source .venv/bin/activate    # Linux / macOS

# 2. Install the package in editable mode with test dependencies
pip install -e ".[dev]"

# 3. Configure your API keys
Copy-Item .env.example .env
```

Open `.env` and fill in your API keys:

```dotenv
GEMINI_API_KEY=AIzaSy...
ANTHROPIC_API_KEY=sk-ant-...
```

> **Zero-Install Tip**: If dependencies (`pydantic`, `typer`, `rich`, `pyyaml`, `httpx`, `google-genai`, `python-dotenv`) are already installed in your base Python/Conda environment, you can run any command directly without `pip install -e .` by prefixing it with `$env:PYTHONPATH="src"; python -m orchestrator.cli ...` instead of `orch ...`.

## 3. How to Use the Tool Daily (CLI Commands)

Once installed, everything is accessible through the `orch` CLI.

### 3.1 Preview the Animated Terminal Scene (`orch demo-ui`)

To watch the Claude-Code-inspired night scene with the **Parent (Planner)** and **Child (Executor)** pixel-art mascots cycle through all 4 orchestration states (Planning, ReAct Execution, `StepRouter` Escalation, Success) without spending any API tokens:

```powershell
orch demo-ui
# Or without installation:
$env:PYTHONPATH="src"; python -m orchestrator.cli demo-ui
```

> **CI/CD & Future MCP Server Note**: `orch run` and `orch plan` display the live animation by default, and support `--no-anim` to disable `rich.live` when piping output to external CLIs or an MCP server.

### 3.2 List Available AI Pairings (`orch pairings`)

Displays all `Planner -> Executor` pairings configured in `config/models.yaml` along with their input/output pricing per 1M tokens:

```powershell
orch pairings
```

### 3.2 Generate an Execution Plan Only (`orch plan`)

Useful to inspect how the Planner decomposes your goal before modifying any project files:

```powershell
# Using the default Planner (Gemini 4 Argon)
orch plan --goal "Create a minimal REST task management API with unit tests"

# Explicitly selecting Claude Opus 5.5 as the Planner
orch plan --goal "Refactor the CSV parser module" --planner claude-opus-5.5 --max-budget 1.00
```

### 3.3 Run a Full Goal on a Project (`orch run`)

Runs the complete lifecycle: **Initial Planning → Step-by-Step Execution (ReAct loop) → Conditional Escalation → Final Cost Summary**.

```powershell
# Run with default pairing (argon-flash) and a $1.50 ceiling
orch run --goal "Create a CLI CSV-to-JSON converter with unit tests" --project ./examples/demo_project --max-budget 1.50

# Run with a specific preset pairing (--pairing)
orch run --goal "Build a cyclic graph solver" --project ./examples/demo_project --pairing opus-sonnet --max-budget 2.50

# Mix and match any Planner and Executor on the fly (--planner and --executor)
orch run --goal "Add Pydantic validation" --project ./examples/demo_project --planner gemini-4-argon --executor gemini-3.1-pro --max-budget 2.00
```

### 3.4 Interactive Mode (`--interactive`)

If you want to manually approve each step before the Executor runs it:

```powershell
orch run --goal "Add unit tests" --project ./examples/demo_project --pairing argon-flash --interactive
```

Before each step, the CLI will prompt you for confirmation. Declining skips the step without spending Executor tokens.

## 4. How to Run & Customize Benchmarks

**Ai-Sup** includes a built-in comparative benchmark engine (`src/orchestrator/benchmark.py`) that evaluates **100% Frontier baselines** against **Delegated Plan-then-Execute pairings** across a standardized 10-step software engineering pipeline.

### 4.1 Run the Benchmark in Your Terminal

With `orch` installed:
```powershell
orch benchmark
```

Or directly via Python without installing the CLI script:
```powershell
$env:PYTHONPATH="src"
python -m orchestrator.cli benchmark
```

### 4.2 Export the Benchmark Table to Markdown

To save the formatted Markdown comparison table into a file (e.g., `benchmark_results.md`):

```powershell
orch benchmark --output-md benchmark_results.md
```

### 4.3 Add Your Own AI Pairing to the Benchmark

1. Open `config/models.yaml`.
2. Under `pairings:`, add a new entry—for example, pairing `Gemini 3.1 Pro` with `Gemini 3.8 Flash`:
   ```yaml
   pairings:
     pro-flash:
       description: "Mid-Tier Gemini P-t-E (Gemini 3.1 Pro -> Gemini 3.8 Flash)"
       planner: "gemini-3.1-pro"
       executor: "gemini-3.8-flash"
       baseline: "argon-only"
   ```
3. Re-run `orch benchmark`: `pro-flash` will automatically be evaluated and compared against `argon-only`.

### 4.4 Tune Simulation Profiles (`SIMULATION_PROFILES`)

In `src/orchestrator/benchmark.py`, the `SIMULATION_PROFILES` dictionary defines empirical parameters for each model:
- `plan_input_tokens` / `plan_output_tokens`: token volume per planning call.
- `exec_input_tokens_per_turn` / `exec_output_tokens_per_turn`: token volume per ReAct turn.
- `exec_turns_per_step`: average ReAct turns needed per step.
- `complex_step_failures_before_replan`: number of failures on the hard algorithmic step (`step_4`) before `StepRouter` escalates back to the Planner.

### 4.5 Compare Pairings with Live API Calls

To compare two pairings live with your own API keys on an identical coding task:

```powershell
# 1. Create two clean target directories
New-Item -ItemType Directory -Force ./examples/test_argon_flash, ./examples/test_argon_only

# 2. Run delegated Argon -> Flash
orch run --goal "Write a fib.py module with memoized fibonacci and test_fib.py" --project ./examples/test_argon_flash --pairing argon-flash --max-budget 1.00

# 3. Run 100% Argon baseline on the exact same goal
orch run --goal "Write a fib.py module with memoized fibonacci and test_fib.py" --project ./examples/test_argon_only --pairing argon-only --max-budget 2.00
```

At the end of each run, compare the final summary panel (**Planner Cost**, **Executor Cost**, **Total Cost**) and inspect the generated files.

## 5. Customizing Models, Pairings & Routing Rules

All configuration lives in `config/`:

### 5.1 `config/models.yaml`
- **`models:`**: Defines each model's API `id`, `provider` (`google` or `anthropic`), `input_cost_per_million`, and `output_cost_per_million` in USD.
- **`pairings:`**: Defines named `Planner -> Executor` combinations and their reference `baseline`.

### 5.2 `config/router.yaml`
- **`max_retries_before_escalation: 2`**: After 2 consecutive failures on the same step, `StepRouter` escalates back to the Planner to replan.
- **`min_remaining_budget_for_planner: 0.25`**: When the remaining budget drops below `$0.25`, `StepRouter` blocks expensive Planner escalations and forces the Executor to finish within budget.
- **`shell.allowed_commands`**: Strict whitelist of command prefixes permitted for the `run_command` tool.

## 6. Things to Know (Security, State, Budget & Best Practices)

### 6.1 State Persistence (`state.json`)
- During `orch run --project ./my_project`, the orchestrator creates and updates `my_project/state.json`.
- It stores `completed_steps`, `step_retries`, and `step_outputs`.
- **Important**: If you start a brand-new, unrelated goal in the **same** `--project` directory, delete `my_project/state.json` first so the orchestrator starts with a clean state.

### 6.2 Security & Sandboxing
- **Filesystem Confinement (`tools/file_system.py`)**: `read_file`, `write_file`, and `list_dir` strictly reject paths containing `..`, absolute paths, or symlinks escaping the `--project` root directory.
- **Shell Command Whitelist (`tools/shell.py`)**: `run_command` rejects any command that does not match a prefix in `config/router.yaml` (`pytest`, `python`, `git status`, `git diff`, `ruff`, `ls`). Shell chaining and redirection operators (`;`, `&&`, `||`, `|`, `` ` ``, `$(`, `>`, `<`) are blocked to prevent command injection.

### 6.3 Budget Enforcement (`CostTracker`)
- Remaining budget is checked **before every Planner call** and **before every Executor ReAct turn**.
- Once `--max-budget` is reached, execution halts immediately.
- *Note*: Because output token count is only finalized when an HTTP response finishes, the final in-flight API call may slightly exceed `--max-budget` by a few cents.

### 6.4 Writing Effective `--goal` Prompts
- Be specific about **expected filenames** and **verification criteria**:
  - *Vague*: `--goal "Make a math script"`
  - *Effective*: `--goal "Create calculator.py with add, sub, mul, div (handling division by zero) and test_calculator.py verified with pytest"`

## 7. Troubleshooting (FAQ)

- **`EnvironmentError: GEMINI_API_KEY / ANTHROPIC_API_KEY is missing`**
  Ensure `.env` exists in the repository root and contains the API key for the provider used by your chosen pairing (or export it in your shell: `$env:GEMINI_API_KEY="your_key"`).
- **`PermissionError: Command rejected by whitelist`**
  The Executor tried to run a shell command not listed in `config/router.yaml`. Add the command prefix under `shell.allowed_commands` in `config/router.yaml` if needed.
- **`MaxReactTurnsExceeded` on a step**
  The Executor did not complete the step within 4 tool-call turns (`max_react_turns=4`). `StepRouter` increments the retry counter for that step and automatically escalates to the Planner after 2 failures.
